🧠 Teori – centrala begrepp (sammanfattning)

🔹 Vad är routing?
- Att visa olika komponenter baserat på URL
- URL → vilken komponent som renderas

🔹 SPA-navigation vs traditionell navigation
- Traditionell: ny HTML från servern
- SPA: JavaScript byter vy, sidan laddas inte om

🔹 Varför routing i React?
- Struktur
- Användarupplevelse
- Bokmärken / delbara länkar
- Större applikationer

💻 Code-along – Grundläggande React Router

🎯 Syfte:
- Visa hur routing styr UI
- Koppla URL → komponent
- Förstå rollfördelningen mellan Router, Routes, Route och Link

🗣️
“Vi bygger inte ‘en app med sidor’ – vi bygger en app som reagerar på URL:en.”

🧠 Innan vi börjar:
Vi bygger inte nested routes, parametrar eller avancerad routing idag.
Fokus är: förstå grunderna.

--------------------------------------------------

📂 Grundstruktur i src/

├─ components/
│  └─ Navigation.jsx   (valfri, vi kan ha nav i App idag)
│
├─ pages/
│  ├─ Home.jsx
│  ├─ About.jsx
│  └─ NotFound.jsx
│
├─ App.jsx
└─ main.jsx

🗣️
“Vi delar upp projektet i pages och components.”

🗣️
“Pages är sådant som hör till routing – alltså sådant som visas via URL.”

🗣️
“Components är återanvändbara delar som navigation, header, footer, cards osv.”

📄 Filernas ansvar

main.jsx

Startpunkt för appen

Här kopplar vi in BrowserRouter
---
App.jsx

Innehåller Routes & Route

Bestämmer vilken sida som visas
---
pages/

Varje fil = en sida

Home → /

About → /about

NotFound → *
---
components/

UI-delar som kan återanvändas

Navigation, Header, Footer osv.

🗣️
“Detta är ingen React-regel – men det är ett väldigt vanligt och vettigt mönster.”

🧩 Steg 1 – Installera React Router

I projektet:
npm install react-router-dom

🗣️
“React Router är ett externt bibliotek – React har ingen routing inbyggd.”
👉 react-router-dom bygger ovanpå react-router
så installeras även react-router automatiskt som dependency.

Annars kommer detta saknas:

Link

NavLink

BrowserRouter (webbimplementation)

DOM-specifik funktionalitet

“Dokumentationen visar ibland kärnpaketet.
Men i praktiken, för webben, använder man alltid react-router-dom.
Det är wrappern runt core-biblioteket.”

🧩 Steg 3 – Skapa sidor (pages)

Home.jsx
  function Home() {
    return <h1>Home</h1>;
  }
  export default Home;

About.jsx
  function About() {
    return <h2>About</h2>;
  }
  export default About;

NotFound.jsx
  function NotFound() {
    return <h2>404 – Page not found</h2>;
  }
  export default NotFound;

“Varje sida är bara en vanlig React-komponent.”
“Routing handlar inte om magi – bara om vilken komponent som visas.”

--------------------------------------------------

🧩 Steg 4 – Routes & Route (regelboken)

I App.jsx:

 import { Routes, Route, Link } from "react-router-dom";

  import Home from "./pages/Home";
  import About from "./pages/About";
  import NotFound from "./pages/NotFound";

  function App() {
    return (
      <>
        <nav>
          <Link to="/">Home</Link> |{" "}
          <Link to="/about">About</Link>
        </nav>

        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          <Route path="*" element={<NotFound />} />
        </Routes>
      </>
    );
  }

  export default App;

🗣️
“Routes = regelbok”
“Route = om URL matchar → rendera komponent”
“* betyder: om inget annat matchar.”

“Link ersätter <a> i en SPA.”
“Den byter URL – utan att ladda om sidan.”

🧪 Steg 5 – Testa appen 

🗣️
“Nu pausar vi och testar.”
“Alla ska se detta fungera innan vi går vidare.”

Testa:

Klicka Home → About

Ändras URL?

Laddas sidan om? (nej!)

Testa skriva /test i adressfältet → 404

🗣️
“Detta är routing.”
“Vi har flera ‘sidor’ – men bara en HTML-fil.”

🧠 Viktiga poänger att säga högt

Routing ≠ nya HTML-sidor

URL styr vilken komponent som renderas

Link gör navigation utan reload

Routes är regelbok – inte UI
